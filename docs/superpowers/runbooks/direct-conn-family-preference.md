# Runbook — 直连族偏好（`direct_conn_family`）

> 对应 spec：`docs/superpowers/specs/2026-10-21-direct-conn-family-preference-design.md`
> 对应计划：`docs/superpowers/plans/2026-10-21-direct-conn-family-preference.md`

## 这个开关解决什么问题

某些网络环境下，一台机器**只有 IPv4 出口**（WiFi 没有 IPv6），而另一台**只有 IPv6 可达**
（例如通过手机热点/蓝牙 PAN 拿到的蜂窝 IPv6）。

默认行为是「先到先得」：IPv6 那边先连上，就一直用 IPv6 —— 但那条路可能是
**手机热点带宽极低**的通道（本机场景），而真正想要的恰恰是「用 IPv4 打洞，成功后切到 IPv4 走流量，
IPv6 留着当回退」。

`direct_conn_family` 就是把「哪一族优先用于**直连**」从隐含行为变成显式配置。

## 三种取值

| 取值 | 含义 |
| --- | --- |
| `auto`（默认） | 与上游完全一致：先到先得，按延迟选路，直连侧不做任何族偏好，不加轮次上限。**不改这个开关 = 行为零变化。** |
| `prefer_ipv4` | 优先用 **IPv4** 建立直连并承载流量；IPv6 连接保留作回退。已存在 IPv6 直连时**不会**因此放弃 IPv4 尝试。 |
| `prefer_ipv6` | 反向：优先用 **IPv6** 建立直连并承载流量。 |

**非法值 / 空串 → 回落 `auto`**（消费点 `ConnFamilyPref::from_flag_str`，配置层不改写你填的值）。

## 怎么配

三处等价，任选其一：

### CLI

```bash
easytier-core --direct-conn-family prefer_ipv4
```

（`--help` 里能看到该参数；环境变量形式为 `ET_DIRECT_CONN_FAMILY=prefer_ipv4`）

### TOML

```toml
[flags]
direct_conn_family = "prefer_ipv4"
```

### 网页配置页

「高级设置」→ **直连地址族偏好** → 三态下拉（自动 / 优先 IPv4 / 优先 IPv6）。
桌面 GUI 与网页配置服务器共用同一份表单。

> 默认值是「自动」，**没动过这个控件就不要往配置里写这个字段**。

## 运行期行为

- **改了不用重启实例**：最多 **5 秒**内生效
  （直连连接器实时读 flag；选路层的偏好缓存每 5 秒刷新一次）。
- **偏好族打不通时会收敛**，不会无限重试：
  1. 一个窗口内最多 **3 轮**（约 15 秒，沿用既有退避 1s/2s/2s）；
  2. 失败后 **冷却 120 秒**；
  3. 连续 **5 个窗口**（约 9 分钟）仍失败 → **放弃**该 peer 的偏好族尝试。
  4. 放弃后会在以下任一情况恢复：偏好设置变化、或该 peer 的连接集合变化。
- **降级链**：
  - 偏好族打不通 → 保留已有的另一族连接继续用（流量不会断）；
  - 若该 peer **当前一条连接都没有** → 允许用另一族兜底建一条连接（保可达）；
  - 偏好族打通 → 流量切到偏好族，另一族连接**不关闭**（可随时回退）。

## 影响范围

- **只影响直连（打洞）路径的族选择**。
- **不影响**：中继（relay）选路、IPv6 监听开关、协议线格式、其它任何 flag。
- `auto` 下所有判定与上游**逐位一致**（排序键第二分量恒为 0，直连侧不做族过滤，打洞层保持原语义）。

## 排障

| 现象 | 排查方向 |
| --- | --- |
| 配了 `prefer_ipv4` 但流量仍走 IPv6 | 偏好**只排序、不强制**：IPv4 洞没打通时会继续用 IPv6。看日志里有没有 IPv4 直连建立成功的记录。 |
| 对端完全连不上 | 先用 `auto` 验证对端本来能连；再对比 `prefer_*` 下的日志。偏好族不通时，另一族兜底只在「该 peer 尚无任何连接」时生效。 |
| 想知道当前实际走的是哪条路 | `easytier-core` 日志级别调高后能看到连接建立与选路信息；`PeerConnInfo` 里的 tunnel 地址可判断族。 |
| 想临时恢复默认 | 把值改回 `auto`（或删掉该字段），运行期 5 秒内生效。 |

## 已知限制

- **打洞产出的连接族不可控**：TCP 对称打洞连的是对端的**映射地址**，族由对端 NAT 决定，
  本地无法指定；UDP 对称打洞固定产出 **IPv4** 路径。
  因此 `prefer_ipv6` + TCP 打洞可能打不出 IPv6 路径（UDP 打洞同）。
- **对端主动打进来的连接也算数**：打洞是双向的，对端通过 server-side punch
  打过来的连接（同属 punch 来源）也计入收敛——本端相应传输会因此
  **停止重复发起**打洞，符合 spec §10.2 的既定语义，不是 bug。
- 域名形式的对端 listener（`tcp://example.com:11010`）在偏好模式下只解析偏好族。
